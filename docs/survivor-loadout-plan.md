# 雙手裝備、身體狀態與負重：獨立候選施工方案

盤點日期：2026-10-30。基準 `main@5eae3e5207ad355dc0e41bda8321620ec17dec1f`。
本分支只準備方案；尚未改遊戲行為，不代表雙持已可玩。不部署、不合併。

## 使用者方向與邊界

上海仍是真實街區，操作參考暗黑式直覺戰鬥，生存資訊借鑑 Project Zomboid；不是搬用其素材、逐項複製醫療模擬或把現有遊戲改為回合制。優先順序為美式視覺質感、操作、玩法。採原創深炭灰／骨白／暗紅的裝備介面，清楚的裝備剪影、身體輪廓與狀態標示，不用大量花哨功能掩蓋手感。

獨立近戰動畫施工保有 `characters.ts`、`animateRig`、`startSwing` 和武器掛點的所有權；本方案不能直接覆蓋。PR #2 `feat/shanghai-identity-details-20261030@782d3a1` 仍為 draft，其室內外、遮擋與房間面板不列入本分支。兩支共用 `survival.ts`，整合應用小範圍適配函式，不複製整份檔案。

## 現況（已讀原始碼）

| 範圍 | 目前實作 | 直接限制 |
| --- | --- | --- |
| 武器 `arsenal.ts` | v1，`owned: WeaponId[]` 唯一 ID；單一 `equipped`；9mm 與步槍彈兩種共享庫存 | 不能擁有兩支同型手槍；步槍／手槍只有一個右手掛點 |
| 戰鬥 `survival.ts` | `action` 全域互斥；`fire()` 消耗對應子彈，含 LOS；近戰鐵管與槍互斥 | 不能直接加第二次 fire 變成無代價雙倍輸出；不能打斷近戰命中窗 |
| 隨身／安全屋 `campaign.ts` | 六個數量欄位 water/food/medkit/battery/ammo/pistol；庫存逐一存取 | 無負重、容量、分類或獨立物件；`pistol` 是歷史相容 token，不可再次兌換槍／彈 |
| 身體 `outbreak.ts` / runtime | HP、體力、水分、飽足、虛構暴露壓力；跑步耗體力，缺水減速；醫療包瞬間回血 | 無傷口、流血、疼痛／疲勞或部位資料；暴露不是醫學感染率 |
| 存檔 | Snapshot v1、map 對應 localStorage key；optional arsenal/helper；每3秒及 pagehide 原子儲存 | 嚴格 inventory 欄位數與 arsenal 欄位數；加欄位會破壞舊驗證器 |
| 手機 | 左搖桿、情境攻擊／搜刮鍵、蹲、背包、暫停；背包暫停模擬 | 現有背包是 330px、60vh 捲動清單，小字；不宜再把功能全部塞同一長列 |

`syncArsenal()` 的 `ammo/hasPistol/pistolEquipped` 是相容鏡像，canonical arsenal 優先。一般槍彈 loot 直接加入 arsenal；每日 ammo cache 是可轉移的補給包，使用才轉 6 發，重量不可重複算。
`isCompatibleSave()` 額外檢查 shelter ID、箱數、敵人數與派系；本工程不得變動這些世界結構。

## 最小完整第一階段（完成才稱可玩）

以「拿一把手槍＋一把鐵管 → 看清狀態 → 搜刮變重 → 回家存放／處置 → 存檔續玩」為一個閉環。

1. **雙手裝備**：主手／副手槽；支援鐵管＋一把已擁有手槍。步槍標示雙手，裝上後副手不可用。所有動作共用現有 action/cooldown，保留牆遮擋與彈種約束。第一階段不聲稱雙手槍；重複武器必須等實例化。裝備交換不生成物品或子彈。
2. **操作**：左鍵／手機主攻擊沿主手；副手用獨立、標示清楚的按鈕，不能搶走 Q 推開、E 情境互動、J 原近戰。鍵位在動畫支線接口對齊後再固定。手機新增副手鍵需真機尺寸／橫直屏測試；沒有副手時隱藏而不是假可點。開包、關包、失焦、pointercancel 必須清空 held 狀態。
3. **負重**：先採計數式背包＋分類與重量，不做格子拼圖。物資、已擁有槍械和散彈各算一次；stash 不計負重。軟上限造成漸進移速／體力代價，不刪除舊超量物資、不硬鎖住舊玩家。保留逐一存取與資源守恆。
4. **身體**：先全身狀態卡＋一種可理解的傷口／流血模型（明確是遊戲規則），暫不虛構六部位受擊精準度。現有敵方實際命中才加傷口；空揮／被牆擋不加。醫療包處置並保留原有效果；有成本的安全屋休息改善傷勢。暫停、背包、屋內不偷跑流血時間，死亡只結算一次。
5. **介面**：裝備、背包、身體三頁籤；手機至少 44px 點擊目標、安全區、可捲動內容與固定關閉鍵。桌面精簡 HUD 保留 HP／體力，將餘下細節移入身體卡。紅色之外亦用文字／圖標表示狀態，不能只靠顏色。
6. **完整性**：舊存檔進入、全流程操作、刷新續玩、快速挑戰不污染沙盒、既有測試全跑、桌面與手機截圖全部達標後才開候選 draft PR；不直接上線。

## 相容設計

- 保留 Snapshot v1、現有 saveKey 與 inventory 六欄；不要把物品重量或 UI 派生狀態寫回原 inventory。
- 新增 optional、自己版本化的 `survivorSystems: {version:1, hands, condition}` 擴充；不存在時依舊裝備推導單手／雙手、傷勢預設健康，原 HP／彈藥／物資不變。存在但非法時明確拒絕，不能偷偷重置為健康。
- `arsenal` 原結構不擅改；只是一支手槍＋鐵管的過渡方案。hands 與 canonical equipped 以一個裝備交易更新；讀檔檢查所有權、雙手限制與鏡像一致，失敗不部分套用。
- 如必須做到兩支同型槍，第二階段採唯一 instance ID 與 migration；不能把 `owned` 放重複 ID 或從 legacy pistol token 生出第二把槍。
- 新版本可讀舊檔不等於舊版本可安全寫新檔：舊 runtime 會忽略擴充且下一次存檔刪掉它。候選測試須使用隔離 origin／storage profile，先保留原 raw save 備份；不得讓正式版本與候選版本交替寫同一份檔案。發布遷移前制定明確回退備份流程。
- 錯誤／配額不足保持上一次有效資料；轉移、loot、使用與裝備都先驗證後原子提交，不能先標記箱子已搜再發現背包失敗。

## 分階段落地與檔案界線

**0：本分支（已準備）** — 唯讀盤點、基準回歸與設計；沒有 runtime diff，不干擾其他施工。

**1A：純規則核心** — 新增 `loadout.ts`、`body-condition.ts`、`carry-load.ts` 與 Node 測試；在 `campaign.ts` 加擴充驗證／遷移與 legacy fixtures。所有規則不依賴 Three/DOM；提供派生狀態與 action intent，不直接操作骨架。

**1B：最小完整可玩整合** — `survival.ts` 僅接裝備／負重／命中／醫療／存取／存檔適配器；新 UI 模組＋獨立 CSS；手機 controls 加副手 action。動畫分支提供 hand socket 與動作入口後再掛左右武器。與 PR #2 同時修改的片段逐段 review、跑雙方回歸，不能以整檔覆蓋解衝突。完成上述第一階段閉環。

**2：物品實例與細化傷勢** — 真正兩把同型槍、各自耐久／彈匣；背包容器容量與快速轉移；可追蹤受擊來源後才做頭／軀幹／四肢傷勢與針對處置。明確新的存檔版本與前向遷移，不能增加重複 canonical 狀態。

**3：手感與生存深度** — 雙持平衡、疲勞、負重動畫與打擊反饋；音效與原創風格統一。是否做裝填、衣物保護、感染等另按實玩結果決定，不提前堆功能。

## 驗收清單

- 單元：無副手／手槍＋鐵管／雙手步槍；未擁有不能裝；不能雙倍消耗或發彈；非法數值／NaN／未知版本不變異。
- 資源：水 food medkit battery ammo pack、散彈與槍重量各一次；使用／拆包重量變化合理；存取總量守恆；舊超重檔能繼續移動與卸物。
- 傷勢：只在命中產生；dt 無效無作用；暫停不消耗；處置有物資成本；休息時間只推進一次；死亡與續玩規則一致。
- 存檔：無 arsenal 的最舊檔、有 arsenal 現行檔、新擴充檔、損毀檔、容量拒絕；reload 保持裝備、彈藥、傷勢、世界耗盡紀錄。
- Runtime：實際操作入口走上述規則，不只測純函式；quick mode 不改 sandbox 存檔。
- 瀏覽器：桌面 1440×900；觸控 390×844 與橫屏；重複開關、切頁、失焦恢復、按住攻擊開包、長清單、空背包、滿負重、武器耗盡、屋內存取及自然操作刷新續玩。
- 截圖只證明畫面；操作／存檔必須附 console、狀態斷言及操作紀錄。基準 Node 腳本不是瀏覽器實玩。
